# 최종 제안 — md 없이 JSON 정본만으로 검색·컨텍스트를 만드는 방법

날짜 2026-09-02. 이 문서의 숫자는 전부 다른 워커가 적대적으로 재검증한 것만 쓴다. 검증에서 깨진 주장은 "쓰지 않는 것" 절에 따로 적었다. 조사만 했고 정본·scripts 는 손대지 않았다.

근거: bench/V3_REPORT.md(claude N) ← bench/review_v3/REVIEW.md(codex P) / bench/VECTOR_NAT_REPORT.md(codex O) / bench/NATURAL_SYNTHESIS.md / bench/SYNTHESIS.md / bench/review_inc/REVIEW.md.

## 1. 제안 한 줄

**md·qmd 경로를 없애고, build 때 굽는 sqlite 색인 하나로 검색하며, 답은 행 단위로 고른 block 을 block 단위로 예산에 채워 JSON 부분 그래프 형식으로 넣는다. 벡터는 넣지 않는다. 무주입 문턱은 기본으로 켜지 않는다.**

## 3. 넣지 않는 것과 이유

| 넣지 않는 것 | 이유 (검증된 숫자) |
|---|---|
| 벡터(qmd) 폴백 | 자연 세트 page 검색: 언어 교차 어휘 0.48 → 벡터 0.64, 두 목록 합집합 상한 0.84 인데 실제 RRF 융합은 0.56. 바꿔 말하기는 이득 0. page 를 찾아도 어휘 block 선택이 0.08 로 무너지고, block 벡터로 0.44 를 얻으려면 상주 713 ms. 어휘 신호가 약할 때만 부르는 조건부 호출도 무관 질문의 95% 를 부른다. qmd 에 후보 재정렬 API 가 없다. 색인 254 s, 61.7 MB, 모델 333 MB |
| 무주입 이진 문턱 (기본값) | 오탐 5% 를 지키는 어떤 신호·조합도 answerable 주입 ≤ 0.47 이고 바꿔 말하기는 0. 같은 도메인의 답 없는 질문(hard negative) 분포가 답 있는 질문과 겹친다. v3 의 "등급" 경계(770/777)는 실제로 99.3% 이진이며 분할을 바꾸면 0.39~0.55 로 흔들린다 |
| heading 경로를 block 본문에 붙여 색인(H6) 을 기본값으로 | 이 세트에서 +0.060 이지만 질문에서 heading 어휘를 빼면 −0.049. 질문 74% 가 heading 어휘를 담는 세트라 일반화 불가. 옵션으로만 두고 두 번째 자연 세트에서 다시 잰다 |
| alias 필드 | 합성·자연 어디서도 기여 0 |
| history.at 순위 신호 | 자연 세트에 최신성 질문이 없고 합성 세트는 날짜가 인공물. 판정 불가 |

## 4. 무주입은 이렇게

기본값은 **문턱 없음(항상 본문)** 이다. 근거: 문턱을 켜면 정답 전달 0.543 → 0.478(무관 바이트 3,354 → 881) 이고 분할에 따라 0.39 까지 내려간다. 무관 질문에 3.4 KB 를 더 쓰는 비용은 하루 100 프롬프트 중 절반이 무관이라 해도 약 125 KB/일 ≈ 4.2만 토큰/일 ≈ $0.21/일(Opus 5 입력가) 이다. 정답 전달 12%p 를 그 값에 팔지 않는다.

문턱을 켜고 싶으면 옵션으로 둔다: `raw_top × coverage < 770` 이면 무주입. 이 값은 동결 자연 세트에서 고른 값이고 다른 위키에서는 그 위키의 질문 로그로 다시 잡아야 한다. 이것을 기본값이라고 부르지 않는다.

## 5. 반박 가능한 지점을 미리 적는다

1. **자연 세트는 334 page 하나다.** 정확도 절대값(0.543)은 이 세트 안의 값이다. 다른 위키에서 같은 값이 나온다고 주장하지 않는다. 규모(만 건) 결론은 합성 세트에서만 나왔고, 합성 세트는 정확도 근거로 쓰지 않는다.
2. **질문 작성 인공물.** 질문을 문서를 보고 썼기 때문에 heading 어휘가 많다(74%). H6 를 기본에서 뺀 이유다. H1·H5·W4·block 채움·fold 는 heading 어휘를 제거한 반사실에서도 손해가 없었다.
3. **행 단위 전달의 320자 상한은 현재 구현에서 321자까지 나온다** (생략 표시 1자). 구현 시 마지막에 다시 자른다.
4. **합성 회귀 0 은 H5 와 제목 block 제외에 대해서만 검정됐다.** H1 의 heading 부분과 H6 는 합성 코퍼스에 heading 이 없어 검정되지 않았다.
5. **비용은 두 관측점이다.** 색인 크기 +7.7%(합성, heading 없음) ~ +41%(자연, heading 많음). 조회 +0.7 ms.
6. **세트 자체의 한계 31문항** (이전판으로도 맞는 3, span 이 답의 일부 4, 흔한 span 11 등). 결과 해석을 바꾸는 것은 14문항이고, gold·개정 체인 귀속 지표(0.511)가 그 영향을 뺀 값이다.
7. **언어 교차·바꿔 말하기는 여전히 낮다** (0.24 / 0.19). 어휘 검색의 한계다. 벡터가 page 는 살리지만 block 을 못 살린다는 것까지 쟀고, 그 이상은 이번 범위 밖이다.

## 6. 구현 순서 (별도 지시 시)

1. `scripts/llmwiki.py build` 에서 `index/markdown`·`search.json` 생성 제거, `export_markdown` 제거. `llmwiki_context.py` 의 `qmd_slugs` 제거. (무손실)
2. `scripts/llmwiki_index.py` 신설: structural3 의 색인(H5, 제목·heading evidence 제외)·검색·supersedes head + 투영 표. build 때 굽고 `VACUUM INTO` 로 publish. WAL.
3. `llmwiki_context.py`: `open_index` → 없으면 지금의 스캔으로 fail-open; `retrieve` 를 색인 조회로; 페이로드를 v3 형식(행 단위 선택 + block 단위 채움 + P/B/E)으로; 바이트·토큰 둘 다 검사; 모든 출력에 `redact`.
4. 증분 갱신: `page_hash_map(changed)` + `map_delta` + `apply_delta` + `refresh_graph(touched)`; 감시자가 `--changed` 를 넘긴다.
5. 옵션: 무주입 문턱(기본 꺼짐), H6 heading 경로 색인(기본 꺼짐).
6. 두 번째 자연 세트(다른 저장소, 질문은 문서를 보지 않고 쓴 것)에서 1~5 를 다시 잰다.
